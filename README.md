 # Battery Telemetry ML

 One-line: end-to-end demonstration of an ML pipeline that predicts instantaneous power and remaining battery runtime from device telemetry (synthetic data).

 This repository contains a reproducible pipeline to:
 - generate synthetic telemetry data (voltage, current, temperature, load state),
 - create defensible derived features,
 - train and compare Linear Regression, Random Forest, and XGBoost models,
 - evaluate models with MAE / RMSE / R² on a held-out test set,
 - persist model artifacts and metadata,
 - serve predictions via a FastAPI inference service.

 **Important:** the dataset is synthetic and intended for demonstration only. See "Synthetic data" below for how the data is generated and its limitations.

 ## Quick start

 1. Create & activate a virtual environment (recommended):

 ```bash
 python -m venv .venv
 # Windows
 .venv\Scripts\activate
 # Unix / macOS
 source .venv/bin/activate
 ```

 2. Install dependencies:

 ```bash
 pip install -r requirements.txt
 ```

 3. Full reproducible demo (generate → train → evaluate):

 ```bash
 # generate deterministic synthetic dataset
 python -m battery_prediction.cli generate --out data/telemetry.csv --n 3000 --seed 123

 # train models (train/val split, CV) and save artifacts
 python -m battery_prediction.cli train --data data/telemetry.csv --out models --seed 42

 # evaluate saved models on an untouched test set
 python -m battery_prediction.cli evaluate --data data/telemetry.csv --models models
 ```

 4. Run the inference API (serves models found in `models/`):

 ```bash
 python -m battery_prediction.cli serve --port 8000
 ```

 Then POST JSON to `http://localhost:8000/predict` with fields `voltage`, `current`, `temperature`, `load_state`.

 ## Project structure

 - `battery_prediction/` — main package containing data, features, models, API, and visualization modules.
 - `data/` — (ignored by default) generated telemetry CSVs.
 - `models/` — (ignored by default) saved model artifacts and metadata JSON files.
 - `results/` — evaluation metrics CSV and plots produced by the pipeline.
 - `scripts/` — convenience scripts: `demo.py`, `generate_reports.py`.
 - `tests/` — pytest unit tests for generator and API.

 ## Synthetic data (important)

 All experiments use synthetic telemetry generated by `battery_prediction.data.generator.generate`.

 Generation notes and assumptions:
 - Variables produced: `voltage`, `current`, `temperature`, `load_state`, `power`, `minutes_left`, `timestamp`.
 - Voltage and current are stochastically simulated with realistic ranges (voltage ≈ 3.0–4.3 V; current ≈ 0–3 A). Temperature is simulated with modest noise and bounded to plausible device ranges.
 - Load state is sampled from `['idle','light','medium','heavy']` and affects the remaining runtime calculation.
 - Instantaneous power is computed as approximately `voltage * current` plus small noise; negative power values are prevented.
 - Remaining runtime (`minutes_left`) is derived using a simple battery-capacity model: runtime inversely proportional to current (capacity ≈ 3000 mAh) with adjustments for load state and additive noise.

 Reproducibility:
 - The generator supports a `--seed` argument to produce deterministic datasets. When a seed is provided, timestamps are also produced deterministically to ensure byte-for-byte reproducibility when needed.

 Limitations:
 - The dataset is synthetic and uses simplified physical relationships — it is suitable for demonstrating a pipeline but not for production battery management or safety-critical decisions.
 - Performance numbers reported in `results/project_summary.md` reflect this synthetic setup and should not be interpreted as real-world benchmarks.

 ## Feature engineering

 Derived, defensible features are created in `battery_prediction.features.engineering` and include:
 - `power_inst` (voltage × current),
 - `temp_current` (temperature × current),
 - `current_squared` (non-linear current term),

 These features are intentionally non-leaky (derived only from inputs available at prediction time).

 ## Models & evaluation

 We compare Linear Regression, Random Forest, and XGBoost for two targets:
 - `power` (instantaneous power in watts),
 - `minutes_left` (remaining runtime in minutes).

 Evaluation protocol:
 - Train/validation split and cross-validation (CV) are used for hyperparameter selection on the training data only.
 - Final evaluation metrics (MAE, RMSE, R²) are reported on a held-out test set and saved to `results/metrics/` as CSV files. A concise summary is generated in `results/project_summary.md`.

 See `results/project_summary.md` for the latest auto-generated summary (metrics produced by the pipeline). Example entry from the generated summary:

 ## API

 The FastAPI service (`battery_prediction.api.app`) exposes:
 - `GET /` — basic service info
 - `GET /health` — health check
 - `GET /model-info` — loaded model name and targets
 - `POST /predict` — predict with input schema (validated by Pydantic)

 ### Example request

 POST `http://localhost:8000/predict`

 Body:

 ```json
 {
	 "voltage": 3.7,
	 "current": 0.9,
	 "temperature": 25.0,
	 "load_state": "medium"
 }
 ```

 Response:

 ```json
 {
	 "predicted_power": 0.0,
	 "predicted_remaining_minutes": 0.0,
	 "model": "rf"
 }
 ```
